Challenge 1 · Acute care next year

Who may need the ER or hospital next year

From one year of survey answers by 466 real cancer survivors, it ranks who is likely to have an ER visit or hospital stay the next year, and says why, so the care team can call them first.

What it means for a care team

Start the call list with the alert tier. More than half of them needed acute care the next year, against fewer than 1 in 3 overall.

What to do

Use it to order calls, not to diagnose. A red-flag symptom (fever, chest pain, a fall) means call today, whatever the tier.

The clinical insight

Heavy care this year predicts acute care next year

ER visits, hospital nights, many prescriptions and visits matter most. That marks need; it is not a lever. Finding a survivor's first ER visit is the hard, useful next target: no model beats the baseline much there yet (AUROC 0.65 vs 0.63).

Know the limits

  • Associations, not causes. Changing a factor is not proven to prevent an ER visit.
  • Weak ranking for NH Black survivors (AUROC 0.48, n = 47). Use clinical judgement.
  • Survey answers only. The synthetic clinical records (Synthea) added nothing and share no patient key.

Endpoints

JSON over HTTPS, no key needed. Contract in CONTRACT.md.

  • GET/api/c1/survivors→The 199 held-out survivors, highest risk first, each with a status and a one-line reason.
  • GET/api/c1/survivors/:id→One survivor: risk, the factors behind it, red flags and recommendations for care team, coach and survivor.
  • GET/api/c1/metrics→The model card: every metric with its CI, risk tiers, fairness by group and a plain-language summary.

Reproduce

Fixed seed, so a rerun gives the same numbers.

github.com/zaycruz/c1-acute-risk →
  1. npm install

    First copy the MEPS and Synthea data into data/ and set up the Python venv (README › Run it).

  2. npm run build:data

    Trains the model and writes the submission and the served data. About 5 minutes.

  3. npm run e2e

    Checks every live endpoint and the submission file; saves a JSON record under runs/.
